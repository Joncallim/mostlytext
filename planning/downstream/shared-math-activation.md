## Reference identity and original-source ownership

Changing a collapsed/shortcut link's label changes its implicit reference key.
Both adapters must use the same original-source, parser-authorized repair. Put the
renderer-neutral helper in MarkdownEngine (already a dependency of Math, Preview
and ExportService), independent of TeX. It accepts exact source-bound source facts
and actual accepted substitution ranges; it returns nonempty source edits at the
original closing bracket/suffix, converting only affected collapsed/shortcut links
to the original explicit key. Full keys, inline targets and unrelated links remain.
No new URL or HTML capability is synthesized. A transformed label cannot become
a new reference identity. Actual original parser destinations/titles are compared
before/after on the adversarial corpus, including list/quote continuation prefixes,
escaped brackets, Unicode, LF/CRLF/CR, adjacent and multiple equations. Remove only
parser-proved container prefixes from a multiline implicit key; never drop actual
operators or infer from equal-looking target/label strings. A false coordinate or
source binding fails closed before any edit is applied.

ExportService's existing DerivedContentComposer owns applying these plain-source
suffix edits beside accepted fragment splices, before its existing cmark parse.
Use its already parsed source facts, no second complete export pipeline. Only
accepted substitutions request repairs, and add all repairs to source-coordinate
mapping so heading/export location evidence remains accurate. No zero-width source
range, source generation bypass, overlapping contribution or HTML sanitization
exception is introduced. Preserve accepted content/budget/fallback rules. Tests
must prove preserved real targets/titles and unchanged source on rejected/stale/
failed fragments, plus SourceMap accuracy across repairs.

Preview needs trusted original source range/digest on source-derived blocks.
Generated/inline-composed blocks cannot mint source authority by equal text. Its
math transport uses one source-absent nonce registry and scalar-safe attributed
indices, verifies exact-once marker identity, non-code intent and parser source
position covering each generated range, then restores the caller's typed native
attachment or readable literal fallback. An unknown/missing/duplicate marker or
failed provenance degrades the whole affected block to readable source. Apply the
same reference-key repair before Textual. Bound the entire expanded input including
definitions/markers at the existing 64 KiB cap, not merely original block bytes.
No secondary dollar parser may run for generated, pending, empty or capped tails.
An analysis arrival changes native parser identity even if text is unchanged.

## Export repair application and failure scope

The source helper's actual-parser corpus now passes all LF/CRLF/CR, nested quote/
list/lazy continuation, escaped brackets, Unicode adjacency, multiline definition/
title and multiple-equation cases. It demonstrates that raw marker substitution
loses the original reference, while explicit original-key repair preserves actual
parsed destination/title. No new URL serialization is needed.

Add a source/facts context to ExportComposer's private parsed snapshot, only when
bound to the exact request. DerivedContentComposer computes source repairs AFTER
its existing per-fragment admission, then applies them as ordinary source edits
beside accepted sentinels. Record every edit in the existing coordinate map.
Reference suffix edits are nonempty and must not overlap other edits. Check the
exact source/body suffix binding and resulting Markdown byte budget before
allocation. If that shared snapshot cannot prove reference identity (bad binding,
invalid/overlapping repair or expanded input over budget), reject that derived
snapshot atomically, keep original body, and append a localized failure diagnostic.
Ordinary individual contribution rejection remains unchanged and cannot request
an unnecessary repair. Legacy direct composer callers without a source/facts
context retain their existing behavior; production supplies its proven context.
Tests cover actual existing export composition, stale/failed fragment fallback,
reference targets/titles, front matter offsets and heading coordinates. No HTML
URL bypass or second export renderer is introduced.

## Literal delimiter repair discovered by the adversarial corpus

The real parser loses [$x$`tail][] if copying its raw implicit key introduces
a closing backtick across the original label boundary. The 94-character ASCII
corpus found this concrete failure; failed raw logs and exact before-helper/tests
are retained. The helper therefore also protects original unescaped literal
backticks in the visible label, outside actual code/HTML and accepted replacement
ranges, respecting odd/even backslashes. The original reference key remains
unchanged, and source edits are sorted. Seven regressions compare visible decoded
heading text as well as actual targets/titles, including matched code and HTML.
Destination/title and text comparisons use exact UTF-8, so canonical lookalikes
cannot hide a changed target. Only the derived representation changes; the author
source and its equation/navigation coordinates remain immutable.
